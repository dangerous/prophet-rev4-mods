# CLAUDE.md

## Spec
The product spec is `docs/SPEC.md`. Behaviours carry a hardware-verification marker; host
tests enforce them, the marker records whether they were also confirmed on an instrument.

## System type
Embedded firmware patch for the Sequential Prophet-5/10 Rev4 Main OS (ARM Cortex-A5,
Thumb-2, RAM-loaded): our own arpeggiator/step-sequencer engine hooked into stock 2.1.0,
plus a Python CLI that unpacks, patches and re-packs the OS SysEx image.

## Layout
- `fixtures/` — the official Main OS 2.1.0 and Panel OS 1.1.3 `.syx` files go here; they are
  copyrighted and not committed (see `fixtures/README.md`, `fixtures/SHA256SUMS`). Tests read
  them and skip, with a warning, when they are missing.
- `tools/` — Python packing/patching CLI (`python3 -m tools ...`).
- `firmware/` — engine C sources (`arp.c` the arpeggiator, `seq.c` the sequencer, `arpui.c`
  the UI, `oct.c`, `rate.c`, `disp.c`, `vhold.c` portable; `native.c` the hooks and stock
  interface table), built freestanding for `thumbv7a` at a fixed address;
  `hooks_native.json` lists the patched stock sites.
- `tests/` — `unittest` suites for the tooling and the built image; host-side C harnesses for
  the engine behaviour.
- `site/` — the browser patcher published by GitHub Pages (`index.html`, `patcher.js`
  hand-written; `manifest.js` generated by `make manifest` and committed with each image).
- `docs/` — spec, working notes, hardware test checklist, reverse-engineering notes (`re/`).

## Build and test
- `make test` runs everything (Python `unittest` suites + host C harnesses). Single suite:
  `python3 -m unittest discover -s tests/tooling -t .`, `make test-firmware`.
- `make image` builds `build/prophet10_native.syx`; `make manifest` regenerates `site/manifest.js` from it.
- Tests use the stdlib `unittest` runner (no third-party packages are installed on this
  machine; do not add dependencies).

## Acceptance tests
- Tooling: `unittest` against `fixtures/` — byte-exact round-trips and structural
  validation of built images (records, XOR check bytes, lengths, hook-site disassembly).
- Engine behaviour: portable C compiled natively and driven by harnesses that fake the stock
  voice allocator, display, LED and panel. Tests feed key/button/pot/hold/MIDI events and
  ticks and assert the exact note-on/off sequence and timing.
- Hardware: manual checklist in `docs/hardware-checklist.md`; results recorded as spec
  markers.

## Conventions
- Python: stdlib only, 3.9+, `unittest`. C: C11, no libc dependence in firmware sources
  (no hardware divide on the A5: the EABI helpers live in `native.c`; avoid 64-bit shifts).
- Never commit anything under `build/`. Never edit `fixtures/`.
- `dist/*.syx` is git-ignored, so it is **per checkout**: after building in a worktree, copy
  the image into the root checkout's `dist/` (that is where it is flashed from) and check
  `cd dist && shasum -a 256 -c SHA256SUMS` there. Never delete dist files; superseded builds
  go to `dist/old/` with a hash suffix.
- Flashing is a human step; the tools only produce files.
